# Воксель Бокс

Мобильный воксельный бокс от первого лица с разрушаемым соперником. Вся игра собирается в один самодостаточный HTML-файл (`dist/index.html`), единственная внешняя зависимость — three.js r128 с cdnjs. Интерфейс на русском. Автор проекта — Руслан, общение с ним на русском, коротко и по шагам.

## Команды

```bash
npm install                      # playwright + three@0.128 (нужны только тестам)
npx playwright install chromium  # один раз, браузер для тестов
npm run build                    # src/* -> dist/index.html и dist/test.html
npm run serve                    # раздать dist/ на :5173 (открыть с телефона в той же сети)
npm test                         # build + smoke + soak (минимум после любой правки)
node tests/soak.js <seed> <кадры> '<читы JSON>' '<опции JSON>'
node tests/monkey.js <seed> <секунды> '<читы JSON>'
```

Тесты идут в headless Chromium с программным рендером (swiftshader). Время JS в них достоверно, время GPU — нет: FPS из тестов не переносить на телефон.

## Как устроен код

- `src/` — куски одного скрипта. `build.js` склеивает их в строгом порядке (массив `ORDER`). Это не модули: всё живёт в одной IIFE, которая открывается в `b_core.js` и закрывается в `y_close.js`. Функции и переменные из любого файла видны во всех остальных.
- `src/x_hook.js` попадает только в `dist/test.html`. Там `window.__g` (доступ к состоянию для тестов) и `window.__prof` (профайлер). В `dist/index.html` его нет.
- Стиль исходников плотный: `var`, короткие имена, несколько операторов в строке. Новый код пиши в том же стиле, существующий не переформатируй — диффы должны оставаться читаемыми.
- Подробная карта файлов, систем и констант: `docs/ARCHITECTURE.md`. Прочитай её перед правкой физики, мешинга или разрушений.
- Что сейчас не решено и что уже пробовали: `docs/STATUS.md`.

## Правила, которые нельзя ломать

1. Результат — один HTML без сборщиков и npm-зависимостей в рантайме. three.js только r128 с cdnjs (API новых версий отличается).
2. `frame()` всегда вызывает `requestAnimationFrame`, тело кадра (`step`) обёрнуто в `try/catch`. Исключение в кадре не должно останавливать цикл.
3. Стоп-кадр и слоу-мо ставятся только через `hitStop(f, s, full)`. Прямые `G.freeze=` / `G.slow=` запрещены (исключение — сброс в `beginFight`).
4. Во время боя нет синхронной полной перестройки: меши чанков идут через `VBody.process` с бюджетом `MESHB` мс на кадр, поиск оторванных кусков — через очередь `ISLQ` на следующий кадр. Новый соперник строится шагами `foeSteps()`.
5. Счётчики ограничены: `WOUNDS` ≤ 44, `DRIPS` ≤ 70, декоративные верёвки `ROPES` ≤ `ROPEMAX`, куски чистит `trimPieces`. Новая сущность, которая копится за бой, получает свой предел.
6. Цель — телефон: управление одним пальцем, safe-area, портрет и ландшафт. Проверяй вёрстку `tests/layout.js`.

## Рабочий цикл

1. Прочитай нужные файлы `src/` перед тем, как что-то утверждать о коде.
2. Правь `src/`, не `dist/`.
3. `npm test`. Для физики и разрушений дополнительно `node tests/gore.js`, `node tests/knockdown.js`, `node tests/body.js`; для отсечения граней — `node tests/cull.js`. Скриншоты пишутся в `shots/` — открой и посмотри глазами.
4. Независимые тесты запускай параллельно.
5. Коммить после каждой рабочей версии (git — единственная история версий проекта). Без `--no-verify` и force-push без подтверждения.

## Доступные инструменты
